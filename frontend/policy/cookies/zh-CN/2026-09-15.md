## 1. 什么是 Cookie

Cookie 是由网站服务器发送到您的浏览器并存储在您的设备上的小型文本文件。它们允许网站在您后续访问时识别您的设备并记住某些信息，例如您的登录状态或语言偏好。

---

## 2. 我们如何使用 Cookie

我们使用 Cookie 的目的**严格限定**于提供核心服务功能，**不会**用于用户追踪、行为分析或广告投放。

### 2.1 Cookie 分类

根据功能用途，我们将 Cookie 分为以下两类：

| 类型 | 说明 | 是否需要同意 |
|------|------|-------------|
| **必需 Cookie** | 服务正常运行所必需，拒绝将导致部分功能无法使用 | 否 |
| **可选 Cookie** | 用于增强用户体验，拒绝不影响核心功能 | 是 |

### 2.2 Cookie 同意机制

当您首次访问本网站时，页面将显示 Cookie 同意横幅，您可以选择：

- **接受**：允许我们设置可选 Cookie；
- **拒绝**：仅保留必需 Cookie，**已存在的可选 Cookie（`selectedLanguage`）将被自动清除**。

您的选择将被记录在 `cookieConsent` Cookie 中，有效期为 365 天。横幅仅在该记录不存在时出现——无论您选择接受还是拒绝，我们都不会反复询问（避免因同一问题频繁打扰您）。

### 2.3 如何撤回您的同意

您撤回同意应当与给予同意同样便捷。当前可通过下列任一方式撤回对可选 Cookie 的同意：

1. 删除 `cookieConsent` Cookie 并刷新页面，横幅会重新出现，此时选择"拒绝"即会清除 `selectedLanguage`；
2. 直接删除 `selectedLanguage` Cookie；
3. 使用浏览器的 Cookie 管理功能删除本站 Cookie（见第 6 章）；
4. 通过本政策末尾的联系方式要求我们协助。

**撤回不影响撤回前基于同意已进行的处理活动的合法性。** 我们目前尚未在页脚提供常驻的「Cookie 设置」入口，上述第 1、2 项是当前的自助撤回路径，我们已将增设该入口列为待改进事项。

## 3. 我们使用的 Cookie 详情

### 3.1 必需 Cookie

以下 Cookie 为服务正常运行所必需，无需您的同意即可设置：

| Cookie 名称 | 设置方 | 用途 | 有效期 | HttpOnly | SameSite | Path |
|------------|-------|------|--------|----------|----------|------|
| `token` | 服务端 | 存放登录用的 JWT Access Token，用于维持登录状态与接口鉴权 | 60 天（**令牌本身有效期 1 小时**，登录后由刷新令牌静默续期） | 是 | Lax | `/` |
| `refresh_token` | 服务端 | 存放会话刷新令牌，**仅用于会话续期**；数据库中只保存其 SHA-256 摘要 | 30 天 | 是 | **Strict** | **`/api/auth/refresh`** |
| `link_token` | 服务端 | 第三方账户（微软/谷歌）绑定流程的确认令牌，用于跳转返回后核验绑定由本人发起 | 10 分钟 | 是 | Lax | `/` |
| `csrf_token` | 服务端 | CSRF 防护令牌（Double Submit Cookie 机制），前端读取后写入 `X-CSRF-Token` 请求头随状态变更请求提交 | 1 天 | 否（前端必须可读才能回传） | Lax | `/` |
| `countdown_end` | 前端脚本 | 验证码发送按钮的倒计时与冷却恢复状态，避免刷新页面后重复触发发送请求 | 动态，与剩余倒计时一致，到期自动消失 | 否 | Lax | `/` |
| `cookieConsent` | 前端脚本 | 记录您对**可选 Cookie** 的接受或拒绝选择，使同意横幅不重复弹出 | 365 天 | 否 | Lax | `/` |

> **需要您知悉**：`countdown_end` 的内容中包含了您在发送验证码时输入的**邮箱地址**（用于页面刷新后恢复正确的倒计时上下文）。它仅保存在您自己的设备上，有效期不超过倒计时时长，我们不会将其写入数据库或日志；若您不希望该信息留存于设备，可刷新页面后删除该 Cookie，或使用浏览器的隐私模式。
>
> `refresh_token` 的 Path 被刻意限定为单一的续期接口——访问本站其他任何接口时，浏览器都**不会**携带该 Cookie，以此收窄凭据的暴露面。`cookieConsent` 本身是记录您选择的技术载体，故归为必需 Cookie；它不构成对您个人信息的分析用途。

### 3.2 可选 Cookie

以下 Cookie 用于增强用户体验，**需要您的同意**才能设置：

| Cookie 名称 | 设置方 | 用途 | 有效期 | HttpOnly | SameSite | Path |
|------------|-------|------|--------|----------|----------|------|
| `selectedLanguage` | 前端脚本 | 记录您的界面语言偏好（zh-CN / zh-TW / en / ja / ko），下次访问时自动切换；同时页面据此标记当前语言，供服务端决定验证邮件的发送语言 | 365 天 | 否 | Lax | `/` |

**拒绝或撤回该同意不影响您的登录、注册、验证码收发等核心功能**，仅意味着下次访问时语言将回退为浏览器/系统默认。

### 3.3 其他本地存储技术

除 Cookie 外，我们对浏览器端存储的使用情况如下，一并向您披露：

| 存储方式 | 是否使用 | 说明 |
|---------|---------|------|
| `sessionStorage` | **是** | 仅两处：`verify_email`（邮箱验证链接跳转后，在页面间传递待验证的邮箱地址，避免重复输入）与头像设置弹窗的待处理状态标记。**标签页关闭即清除，且不随请求发送到服务器** |
| `localStorage` | 否 | 本站不使用 |
| IndexedDB、Web SQL | 否 | 本站不使用 |
| Flash 本地对象（LSO） | 否 | 本站不使用 |
| 设备指纹、Canvas 指纹、字体枚举 | 否 | 本站不实施任何识别设备的采集手段 |
| 像素标签、单向 GIF、追踪脚本 | 否 | 本站不引入第三方分析或追踪代码 |

## 4. Cookie 安全属性说明

我们为不同类型的 Cookie 配置了相应的安全属性：

### 4.1 HttpOnly 属性

| Cookie | HttpOnly | 说明 |
|--------|----------|------|
| `token`、`refresh_token`、`link_token` | 是 | 前端 JavaScript 无法读取，降低 XSS 攻击窃取令牌的风险 |
| `csrf_token`、`countdown_end`、`cookieConsent`、`selectedLanguage` | 否 | 前端脚本必须能读取才能完成相应功能（`csrf_token` 需读取后写入请求头；其余为前端自行写入与恢复） |

### 4.2 SameSite 属性

| Cookie | SameSite |
|--------|----------|
| `refresh_token` | **`Strict`**（跨站请求一律不携带；该令牌仅在站内续期接口使用，不影响跳转流程） |
| `token`、`link_token`、`csrf_token`、`countdown_end`、`selectedLanguage`、`cookieConsent` | `Lax`（均由下发方显式声明，不依赖浏览器默认值） |

`Lax` 的含义是：Cookie 在同站请求中发送；从外部站点点击链接导航进入本站时（GET 请求）也会发送；跨站 POST 请求或由脚本发起的跨站请求不携带。此配置用于在保障第三方跳转登录可用性的同时抑制 CSRF。

### 4.3 Secure 属性

| Cookie | 是否带 `Secure` | 说明 |
|--------|----------------|------|
| `token`、`refresh_token`、`link_token`、`csrf_token` | **是**（生产环境） | 服务端依据站点访问地址是否为 HTTPS 决定该标记；生产环境为 HTTPS，故均带 `Secure`，仅通过加密连接传输 |
| `selectedLanguage` | **是**（HTTPS 页面下） | 前端脚本按当前页面协议判定：处于 `https:` 时显式附加 `Secure` |
| `countdown_end`、`cookieConsent` | **否** | 前端脚本当前未附加 `Secure` 标记。二者不含任何身份凭据（仅倒计时状态与同意标记），实际风险有限，但我们如实披露这一差异 |

全站强制 HTTPS 并启用 HSTS，因此上述未标记 `Secure` 的 Cookie 在正常访问路径下也不会经明文连接传输。

### 4.4 Path 与 Domain 属性

- **Path**：除 `refresh_token` 限定为 `/api/auth/refresh` 外，其余均为 `/`（全站可用）。
- **Domain**：服务端下发时设置为由站点访问地址派生的主机名，即 `www.nebulastudios.top`，与其他子域名相互隔离。**在本地开发环境（`localhost` 或 IP 地址）下该属性留空**，此时浏览器按当前主机名处理，Cookie 不会跨主机共享。

## 5. 第三方 Cookie

**我们不会代任何第三方在其域名下向您设置 Cookie。** 但在下列场景中，第三方会在**其自身域名**下设置并读取 Cookie，我们无法控制其设置行为与用途，其处理活动受各自的隐私政策约束。

| 第三方 | 触发时机 | 说明 |
|--------|---------|------|
| Cloudflare（CDN、DDoS 防护） | 您访问本站页面时即可能触发 | 其基础设施可能设置技术性 Cookie（如 `__cf_bm`、`cf_clearance`）用于流量路由、风控与浏览器/机器人识别 |
| Cloudflare Turnstile（人机验证） | 在开启人机验证的前提下，您执行登录、注册发码、密码重置、修改密码/用户名、注销账户、开关两步验证等操作时 | 会引入验证与挑战相关的 Cookie。**注意**：我们另外会把您的 IP 地址作为 `remoteip` 参数提交给 Cloudflare 的校验接口，详见《隐私政策》第 5.1 节 |
| Microsoft | 您跳转到微软完成账户登录或绑定期间 | 由微软在其域名下设置登录与偏好 Cookie，[隐私声明](https://www.microsoft.com/privacy/privacystatement) |
| Google | 您跳转到谷歌完成账户登录或绑定期间 | 由谷歌在其域名下设置登录与偏好 Cookie，[隐私政策](https://policies.google.com/privacy) |
| 第三方图床 / 头像来源站点 | 您的浏览器直接加载外部头像时 | 该请求同时会将您的 IP 地址与 User-Agent 发送至该站点。本站已通过 `<meta name="referrer" content="no-referrer">` 关闭 Referer 外发，但无法阻止 IP 与 User-Agent 随图片请求发送 |

**您本站的 Cookie 不受上述影响**：我们在使用浏览器"阻止第三方 Cookie"的情况下仍可提供登录与验证等核心功能，因为本站所有 Cookie 均由我们自己的站点下发。

## 6. 如何管理 Cookie

### 6.1 通过我们的网站

您可以在任何时候通过以下方式管理您的 Cookie 偏好：
- 清除浏览器数据后重新访问网站，将再次显示 Cookie 同意横幅
- 手动删除 `cookieConsent` Cookie 后刷新页面

### 6.2 通过浏览器设置

大多数浏览器允许您查看、删除或阻止 Cookie。您可以通过浏览器设置进行以下操作：
- 查看已存储的 Cookie
- 删除所有或特定 Cookie
- 阻止所有 Cookie 或仅阻止第三方 Cookie
- 设置特定网站的白名单

**请注意**：如果您阻止必需 Cookie，本服务的登录、验证码发送等核心功能将无法正常使用。

### 6.3 常见浏览器 Cookie 管理指南

| 浏览器 | 管理路径 |
|--------|---------|
| Chrome | 设置 → 隐私与安全 → 第三方 Cookie |
| Firefox | 设置 → 隐私与安全 → Cookie 和网站数据 |
| Safari | 偏好设置 → 隐私 → Cookie 和网站数据 |
| Edge | 设置 → Cookie 和网站权限 → Cookie 和网站数据 |

## 7. Cookie 政策更新

我们保留随时修改本政策的权利。重大变更将通过**站内通知及注册邮箱**提前**7个自然日**告知。在通知期届满后继续使用本服务，即视为您接受修订后的政策。

**什么构成重大变更**：新增 Cookie 或其他本地存储技术、变更既有 Cookie 的用途、延长其有效期、新增或更换第三方 Cookie 的提供方。其中涉及**可选 Cookie** 的重大变更，我们将**重新征求您的同意**（横幅会再次出现），而非仅以继续使用视为您接受。

**请注意一处机制差异**：站内设有"强制确认"机制，但目前仅适用于《隐私政策》与《服务条款》两份文本；**本 Cookie 政策的变更不会触发强制确认弹窗**，仅以公告方式生效。因此请您留意政策中心的版本更新提示。全部历史版本持续公开，便于您查阅与保存。
