# 0001 · 自持 WebGL2 渲染层

**Status:** accepted (2026-10-21)

## Context

首页星云画布建立在 three 0.186 上。生产包按 source map 归因后的实际构成（首屏最大 chunk，549 KB minified / 141 KB gzip）：

| 来源 | minified | 占比 |
|---|---|---|
| `three/build/three.module.js` + `three.core.js` | 364 KB | 92.9% |
| `three/examples/jsm/postprocessing/*` | 13.8 KB | 3.5% |
| 本项目 `useNebulaField` + 首页组件 | 12.6 KB | 3.2% |

全仓对 three 的使用面是 16 个类、6 个文件，且只有星云用得到它。`WebGLRenderer` 是不可分的整体——材质系统、光照与阴影、纹理上传、几何体、动画随任何一次 `render()` 一起进包，因此"少用一点 three"不构成减重，唯一实质的减重是替换渲染层。

功能清单不变：视觉、交互、入场序列与降级行为全部保持，§0 的闸门不适用。渲染层替换不可逆（依赖一旦删除，回到 three 需要重做整个适配面），故留此 ADR。

## Decision

1. 删除 `three` 依赖。`app/composables/useNebulaField/gl/` 下自建 WebGL2 原语：上下文与尺寸、program 编译与 uniform 缓存、交错顶点缓冲与 VAO、浮点离屏目标、投影/模型矩阵、色彩转换。矩阵与色彩转换是纯函数，进 `test/unit`。
2. 色彩管线约定（本条是不变量，后续改动不得违反）：CSS 读来的色值先 sRGB→linear，写入 RGBA16F 线性目标；泛光全部在线性空间计算；最后一趟做 linear→sRGB OETF，随后叠 ±1/255 抖动，直写默认帧缓冲，此后不再有任何二次转换。底色由不透明全屏四边形承载，不走 GL 清屏色——清屏路径的色彩约定与这条链不同源，混用必然二次提亮。
3. 泛光自持：亮度高通（带软膝）→ 5 级 mip 降采样 + 可分离高斯 → 按 `radius` 加权合成 → 按 `strength` 叠加。`BLOOM` 常量的四个字段语义保持不变。
4. 降级分支：`EXT_color_buffer_float` 不可用即无浮点可写缓冲，走无泛光直出路径；WebGL2 不可用则不初始化画布，页面其余部分不受影响（现状保持）。
5. 分两步交付且各留对照点：先合入无光晕的直连 GL 路径，再补泛光链，两步都经人眼确认后才会删除依赖。

## Consequences

**得：** 首屏 JS 约 −120 KB gzip，去掉一条第三方依赖与其许可；尺寸、混合、清除行为全部在本仓库可见，"three 在背后做了什么"这类隐性行为（背景板二次提亮即一例）不再有来源。

**失：** 约 550–600 行 GL 层归本项目长期维护；DPR、resize、上下文丢失、浮点缓冲可用性由我们处理；将来要加点选、贴图或其它图元，得自己写。

**验证边界：** 视觉回归只能人眼判。开发环境内渲染面板不可见、`requestAnimationFrame` 冻结、截图不可用，因此本改动的自动化门禁只覆盖纯函数（矩阵、色彩、尺寸计算）与产物体积，不覆盖成像结果。
