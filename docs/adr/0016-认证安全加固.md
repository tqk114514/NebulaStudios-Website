# 0016 认证安全加固

## Status

Accepted

## Context

2026-11 对认证服务做了一轮本地红队审查（会话/CSRF、OAuth2 Provider、账号与邮件、TOTP/社交/后台、HTTP/DoS/加密、存储并发六个面），
每条可利用缺陷都以 `tests/security_*.rs` 的失败用例复现。修复涉及请求契约、状态机与 schema，必须记录取舍。

本项目没有真实业务数据；schema 由 `storage/sqlite/schema.rs` 幂等创建，变更后删除数据库文件重新创建（ADR-0003 修订）。

## Decision

1. **JSON 端点强制 `application/json`。** 浏览器可跨站提交 `text/plain` 表单，原实现直接按 JSON 解析会形成登录 CSRF；
   统一经 `JsonBody` 提取器或 `parse_json_body` 门禁，非法媒体类型返回 415。需要“路径/身份检查先于 body 解析”的端点
   （如管理封禁）保留手动解析顺序。
2. **会话响应不可缓存、补标准安全头。** 全部响应默认 `Cache-Control: no-store`、`Pragma: no-cache` 与
   `Strict-Transport-Security`；头像等公开资源在自己的 handler 中覆盖缓存策略。
3. **同名 cookie 一律拒绝。** `cookie_value` 遇到重复 cookie 返回 `None`，不再取第一个；子域注入的 cookie tossing
   不能通过双提交 CSRF，也不能切换会话。401/403 只有请求确实携带过会话 cookie 时才清除，避免零 cookie 请求被用来强制登出。
4. **社交 state 绑定发起浏览器。** `start` 下发 `__Host-nebula_social_state`（HttpOnly/Secure/SameSite=Lax），
   回调必须恒时比较 URL state 与 cookie；登录与绑定流程共用。TOTP 已启用时社交登录不直接建会话，改发一次性挑战，
   二段通过后才签发。
5. **TOTP 防重放与启用即撤销。** `users.totp_last_step` 记录最后成功时间片，`consume_step` 以原子条件更新拒绝旧片；
   启用 TOTP 在同一事务内递增 `token_version`、撤销全部家族并重签当前设备；未验证邮箱不得启用 TOTP。
6. **OAuth 授权码与撤销边界。** 授权码记录签发时 `session_version`；兑换与创建 refresh 家族在同一事务内完成，
   并校验未消费、未过期、版本未变且未被封禁。已消费码再次呈递返回重放，并撤销首次兑换的家族。登出/改密/封禁删除未兑换码；
   撤回第三方授权同时撤销家族与族内 token，并删除该客户端的未兑换码。
7. **限流与昂贵计算。** `/api/oauth/token` 独立严格限额；授权/同意端点与社会化登录发起/回调单独限额。
   `client_secret` 校验在全局信号量内执行（并发 4，单次约 19 MiB），未知 client 也跑哑哈希抹平时序。
8. **一次性能力随会话撤销。** `revoke_all_sessions_in_tx` 同时删除未消费数据导出令牌与未兑换 OAuth 授权码；
   密码重置、登出、封禁、关闭 TOTP 共用该路径。
9. **邮箱与验证码绑定。** 邮箱入库前经 IDNA 转 A-label，同一域名的 Unicode 规范化形式不会产生重复账户；
   验证码记录签发地址，确认时须与账户当前邮箱一致；邮箱变更在应用时删除全部旧未消费验证码。
10. **未验证账号有保留期。** 清理任务删除创建超过 30 天且未验证的账户，释放邮箱与用户名；配置中的管理员邮箱若被
    未验证账号抢占，真实所有者注册时释放该账号。管理员判定统一为“邮箱在名单内且已验证”。
11. **头像按版本落盘。** 文件名为 `{user_id}-{version}.webp`，并发上传不会用旧请求覆盖新版本内容；读取时校验用户仍存在。
12. **存储写冲突可重试。** `rotate` 对 `SQLITE_BUSY`/`BUSY_SNAPSHOT` 有界重试；管理封禁/解封串行化，状态与审计同事务提交。

## Consequences

- 前端必须以 `application/json` 提交写请求；`text/plain` 表单会被 415 拒绝。
- 会话 cookie 名称暂未迁移到 `__Host-` 前缀：重命名需要前端同步改造。重复 cookie 拒绝已封死演示的 tossing 路径，
  但“子域先写入唯一 cookie”的会话固定仍依赖子域可信。
- 限流仍以 TCP 对端 IP 为键。经 Nuxt/反向代理部署时所有请求共享代理 IP，必须在边缘做限流，或后续引入可信代理配置；
  当前不信任 `X-Forwarded-For`，伪造转发头不会绕过限额，但也不能区分真实客户端。
- `/metrics` 仍匿名可读；生产应绑定内网或由边缘限制。
- 密码重置按 ADR-0002 只依赖邮箱所有权，不要求 TOTP；这是既有边界，本轮未改变。
- 公共客户端（无 `client_secret`）仍不能使用 token 端点；接入公共客户端前需单独设计。
- schema 变更（`totp_last_step`、`sent_to`、`session_version`、`family_id`）要求删除旧数据库文件后重建。
