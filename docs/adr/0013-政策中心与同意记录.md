# 0013 · 政策中心与同意记录

**Status:** accepted (2026-11-16)

## Context

ADR-0002 决定政策文档不进仓库，由部署侧以 manifest 描述语言、版本与生效日期，同意记录入库。需要确定后端职责边界、manifest 形态与「当前版本」判定，否则前端与服务端会各自实现一套日期比较，旧版本也可能被写成有效同意。

## Decision

1. **后端只拥有 manifest 与同意记录，不托管文档。** `NEBULA_POLICY__MANIFEST_FILE` 指向部署侧 TOML，启动时校验并加载，修改需重启。`documents[].path` 是站点内绝对路径或 https 地址，文档内容由部署侧提供。
2. **语言集合固定为 `zh-CN` / `en`，每个政策版本两语言必须齐全。** 与 AGENTS §0 的 2 语言决议一致；缺一语言启动失败，避免声称支持而实际缺失（§9.11）。
3. **公开 `GET /api/policies` 返回全部版本，`current` 由服务端时钟判定。** 前端不自行比较生效日期；同一 slug 的当前版本是已生效版本中 `effective_at` 最大者。
4. **同意记录按 `(user_id, policy, version)` 追加一次。** 只接受当前生效版本；旧版本、未来版本、未知政策返回 422 字段错误。重复同意幂等，保留首次时刻。`GET /api/user/consents` 同时返回已同意记录与当前待同意版本，前端不重复实现比对逻辑。
5. **Cookie 同意仍是前端本地状态。** 后端不记录匿名 Cookie 偏好；需要留痕的同意仅指政策版本同意。

## Consequences

**得：** 当前版本与待同意集合只有一套服务端实现；manifest 非法在启动时暴露；政策文档与代码解耦，语言覆盖由启动校验保证。

**失：** manifest 变更需重启；部署侧必须同步提供两语言静态文档；同意记录不提供撤回语义，随用户删除级联清理。
