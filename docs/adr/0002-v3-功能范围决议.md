# 0002 · v3 功能范围决议

**Status:** accepted (2026-10-25)

## Context

AGENTS.md §0 的范围表遗留四个「待定」项。对照 `Reference/README.md` 全量核对 v3 功能清单后，发现三项 v3 实际存在但未入表：用户名登录、账户注销、Turnstile 人机验证。本文记录四项拍板结论与三项表外项处置；表格只留结论（§16），论证与细节在此。

## Decision

1. **Microsoft / Google 社交登录：保留，简化绑定路径。** Google 仍经 Cloudflare Worker 代理（国内网络无法直连，id_token 由 Worker 验签背书），Microsoft 直连，两者均强制 PKCE。社交登录仅对已绑定账号生效，与 v3 一致：未绑定的社交身份一律返回「未绑定」错误并引导先注册 / 密码登录，**不比对邮箱、不自动建号**（v3 的 `handleLoginAction` 从不自动建号）。砍掉的是 v3 的「登录时发现同邮箱账号 → 弹出绑定确认页 → 邮件验证」流程及其进程内待绑定态（§9.4 反例）；绑定 / 解绑只保留设置页的主动入口（走邮件验证确认）。
2. **头像自动同步：砍。** 头像唯一来源是用户在信息页手动上传（上传 → 缩放 → 转 WebP，§0 已定）。v3 的异步转存 + hash 比对 + 哨兵回落整链移除，社交登录不触碰头像。
3. **数据导出 / 导入：只留导出，砍导入。** 用户可自助下载自己的数据（JSON）。v3 的一次性下载授权码（OTAC）是全局单槽位、两个超管并发互相覆盖，属 §9.4 反例——v4 的下载令牌入库，短时效、单次使用；不做导入、合并、覆盖及 OTAC 撤销那套状态。
4. **政策中心 + 同意记录 + Cookie 同意：保留，但政策文档不进仓库。** 政策文档（多语言多版本 Markdown + manifest）是部署内容而非代码，入仓库会造成内容与代码混杂。文档随部署提供，manifest 描述语言、版本与生效日期，前端按生效日期展示（v3 行为不变）；语言范围跟随 §0 的 2 语言决议。同意记录入库，Cookie 同意为前端本地状态。
5. **用户名登录（表外，拍板保留）：** 登录标识为邮箱或用户名（v3 同款 `email = $1 OR LOWER(username) = LOWER($1)` 查找）；注册含用户名字段。
6. **账户注销（表外，默认）：保留。** 邮件验证码确认；与登出、改密、关闭 TOTP 同走会话撤销路径（§9.1）。
7. **Turnstile 人机验证（表外，默认）：保留但受限。** 可经配置开关；凡挂验证码处必须存在非认知测试的替代路径（邮件链接 / TOTP），满足 §9.12 与 WCAG 2.2 SC 3.3.8。

## Consequences

**得：** 范围表无遗留待定项，后端可以从零起步；社交登录砍掉绑定弹窗后少一个页面路由、一条进程内状态与一类并发补丁；政策文档出库后仓库只含代码与配置。

**失：** 社交登录保留意味着 Worker 代理与外部信任链仍在（Google API 变更、官方品牌素材合规需持续跟进）；导出与同意记录各占数据库表；政策内容改动不再有 git 历史，版本管理移到部署侧自负。
