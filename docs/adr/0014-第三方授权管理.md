# 0014 · 第三方授权管理

**Status:** accepted (2026-11-16)

## Context

AGENTS §0 的 OAuth2 Provider 行只锁定了协议端点；同意授权时写审计，用户没有查看与撤销入口，而前端账号区文案已有「第三方授权：查看并管理所有已授权的第三方应用」。授权状态本身已由 refresh token 家族表达（`client_id` + `scope` + `state`），再建一张 grants 表会形成两套事实来源。

## Decision

1. **已授权应用从 active refresh 家族派生，不新增表。** 只统计仍有未过期 active refresh token 的家族——家族存在但 token 全部过期的授权不再展示。
2. **同一客户端多次授权聚合为一条。** `scope` 取并集，`authorized_at` 取最早一次；按 `client_id` 升序返回。
3. **撤销把该用户对该客户端的全部 active 家族置 `revoked`。** 后续 refresh 轮转立即失败，授权列表不再出现。
4. **已签发的第三方 access token 不引入逐客户端 denylist。** 撤销后它们在剩余 TTL（≤ access TTL）内仍然有效，到期自然失效；逐客户端撤销列表会让每个请求多一次状态查询。
5. **端点与审计：** `GET /api/user/oauth/grants`、`DELETE /api/user/oauth/grants/{client_id}`；撤销成功写入 `oauth.grant.revoke` 审计，无有效授权返回 404。

## Consequences

**得：** 不增加表；授权状态只有 refresh 家族一个事实来源；用户可自助查看与撤销。

**失：** access token 在剩余 TTL 内仍有效；同一客户端多次登录合并展示；空家族被清理后授权记录自然消失，没有独立历史。
